# src/web: React web app

React 19 + TypeScript single-page app built with Vite (ADR 011), managed with npm (`package.json` + `package-lock.json`). The look is fixed by `docs/design/reference.png` and `docs/design/DESIGN.md` (`normetry-design-system` skill); every UI change gets a `ux-ui-designer` screen spec before and a review after.

## Stack

- Vite 8, React 19, TypeScript 6 (`tsc -b` with project references; typescript-eslint does not support TypeScript 7 yet).
- Tailwind CSS 4 with the DESIGN.md tokens as the only theme (`src/index.css`): the default palette, font sizes and radii are reset, so `bg-red-500` or `text-sm` do not exist. Colors: `bg-canvas|sidebar|app|card|inset|elevated`, `border-border`, `bg-bubble-user`, `bg-mint`, `text-on-mint`, `bg-teal`, `bg-teal-deep`, `border-teal-border`, `text-text-primary|secondary|muted`, `text-neutral`, status `success|warning|danger` (status only), `text-info` on `bg-info-bg`, `chart-1` and `chart-2` (data: `bg-`, `stroke-`, `text-`), `bg-chart-track`/`stroke-chart-track`, `bg-scrim`. Sizes: `text-caption` 11, `text-small` 12, `text-body` 13, `text-title` 15, `text-value` 20, `text-greeting` 22, `text-kpi` 28, `text-field` 16 (form fields below 640px: `text-field sm:text-body`). Radii: `rounded-sm` 8, `rounded-control` 10, `rounded-card` 12, `rounded-pill`. A missing token goes into DESIGN.md first, then `index.css`.
- Radix primitives (`radix-ui`) for anything with focus or keyboard behavior: Dialog (drawer, sheets, form dialogs), AlertDialog (`ConfirmDialog`, the delete confirmations), Select (establishment switcher), DropdownMenu (account menu, a user's profiles). Styled by hand in the shadcn/ui manner; no shadcn CLI or `components.json` yet, add them with the first generated component.
- TanStack Query for server state; React Router 8 in declarative mode (`BrowserRouter` with `useTransitions={false}`, so a navigation commits with the click and focus moved after it lands on the new view); `oidc-client-ts` for sign-in; Lucide icons (stroke 1.5 set globally on `.lucide`); Inter from `@fontsource-variable/inter` (self-hosted).
- Chat answers stream over `fetch` (the bearer token cannot go on an `EventSource`), parsed by the hand-written reader in `chat/answers.ts`; no SSE library.
- `@microsoft/signalr` for live status (`api/live.ts`, `useLiveStatus(hubUrl, event, …)`): WebSockets only, no negotiation, the access token in the URL (`api.accessToken`), automatic reconnect.
- Not added yet: Framer Motion (CSS covers today's fades and slides), Recharts (charts are inline SVG, `ui/charts.tsx`, until one needs interaction).

## Layout

- `src/main.tsx` builds the UserManager and the auth store; `src/App.tsx` shows the auth screen or the authenticated app (query client, session context, router).
- `src/routes.ts`: the app's routes. `paths` for links and navigations (the builders encode an id once; `paths.inspection(id, { verdict } | { theme })` presets the findings filters), `routePatterns` for `<Route>` and the sidebar's `matchPath` (`settingsSection` is all of Settings), `findingFilterParams` and `hasFindingFilter`, `arrivalState` (the state a link from another screen carries) and `useArrivalKey()` (its reader). No route path, search param name or arrival state is written anywhere else.
- `auth/`: `oidc.ts` (UserManager settings, return-path validation, error classification), `session.ts` (the sign-in state machine as a plain store read with `useSyncExternalStore`, plus `useSession`), `AuthScreen.tsx` (every screen outside the shell).
- `api/`: `client.ts` (the only `fetch` to the backend: `request` returns the response, `get` the JSON; `form` sends multipart; `problemCode` and `seconds` read a refusal's code and a header's seconds), `contract.ts` (the values the API sends that the app compares against, one `as const` object each: `permissions` as `Permissions.cs` names them, `problemCodes`, `documentStatuses`, `inspectionStatuses`, `reviewStatuses`, `actionStatuses`, `verdicts`, `severities`, `sourceTypes`, `answerEvents`; compare against these, never a literal; types that need a value derive it from them, as `Permission` does), `queries.ts` (`/me`, establishments, `can`, `queryFailed`, `queryNotFound` (a 404, or a 400 for a malformed id), `useQueryRetry` (`failed`, `retrying` and a Try again that focuses the heading once it loads; the heading also takes focus when the error goes away some other way, `errorShown`), the query client defaults), one file per context with its response types, path builders (queries and change requests both use them; each id is encoded there once, and no feature writes an API path), keys and query hooks (`chat.ts` with `Citation`, `documents.ts`, `inspections.ts` with `findingPaths` and `actionItemPaths`, `overview.ts`, `profiles.ts`; they build on `establishmentPath` from `queries.ts`), `passages.ts` (`StoredPassage`, the stored copy of a cited passage that chat and inspection citations extend, and `quoteFound`), `send.ts` (`useSend`, the shared hook for changes: their refusal, problem code and `Retry-After` seconds; a 403 refetches `/me`; `refusalText(result, fallback)`, which says a 403 with `copy.common.denied`; no feature compares a status with 403 to pick its text), `live.ts` (`useLiveStatus`: one hub connection per screen, joins the establishment's group on connect, on change and after a reconnect; `onResync` refetches then; `Live` for the connection notice).
- `shell/`: the app frame (`AppShell`: its hooks, then `mainContent`, which picks the screen or the refused card from the per-screen `frames` table), `screens.ts` (`Screen`, the nav list and `screenAccess(me)`: what each screen needs, the nav items it opens and home; `AppShell` and the sidebar both read it), `frame.ts` (the shell's hooks: `useRoutedEstablishment`, `useScreenFocus`, `useSwitcherChoice` with the drawer, `useRetryFocus`, `usePageTitle`), sidebar (nav gated by permission, the current item by `matchPath`), establishment switcher, account menu.
- `establishments/`: selection (the remembered establishment, else the first), its labels (`selection.ts`), and the card main shows when the list is empty or failed.
- `overview/`: Overview (`/overview`, the selected establishment). `OverviewScreen` (header, KPI row, verdicts and results by theme, compliance over time, expiring documents, top risk themes; its sections follow the response, which leaves out what the caller can't read, and `/me` decides only the skeleton) and `overview.ts` (rounding down, the delta, the plotted points, row 3's spans). Its links carry `arrivalState`; links into the findings preset a verdict or a theme with `paths.inspection`.
- `chat/`: Ask the Regulation (`/ask` new conversation, `/conversations/:id` a saved one). `ChatScreen` (list | conversation | source panel, sheets, focus, the polite live region), `ConversationList` (its heading names the sheet below 768px), `ConversationPane` (one per conversation: leaving it aborts the stream), `conversation.ts` (the chat's hooks: `useAnswerStream` (`ask` runs `createConversation`, `postQuestion`, `handleRefusedPost`, `streamIntoTurn`), `useStickToBottom`, `useConversationView`, `useNotFoundFocus`, `useDeleteConversation`, `useWordReveal`; its title ids), `Answer` (claims, `ClaimChip`, system messages), `Composer` (field, send, quota), `SourcePanel` (`RegulationSource` or `DocumentSource`), and `answers.ts` (server data guards, stored messages to turns, `answering`, the SSE reader, quota headers).
- `documents/`: Documents (`/documents` the selected establishment's list, `/documents/:documentId` one document). `DocumentsScreen` (the live connection and the polite region above both routes, focus), `DocumentList` (card, table, drop on the card), `DocumentDetail` (header actions, versions, delete), `detail.ts` (`useDocumentDetail`: the load, Try again's focus, the delete request and the cache after a delete or upload; `useExpiryForm`), `UploadDialog` (new document or new version; the form mounts per opening, closing aborts), `upload.ts` (`useUploadForm`), `parts.tsx` (version text, title ids), `documents.ts` (the hub and its event, `useDocumentLiveUpdates`, file checks, server refusals, status captions and notices).
- `inspections/`: Simulated Inspection (`/inspections` the selected establishment's history, `/inspections/:inspectionId` one inspection, always fetched for the selected establishment). `InspectionsScreen` (the `/hubs/inspections` connection, the polite region, focus), `InspectionList` (card, Run inspection and its refusal notices, table), `InspectionDetail` (header, running card with stepper, radial and theme checklist, failed card, then the completed view), `detail.ts` (`useInspectionDetail`: the load, the title while it loads, Try again, the focus on arrival and once it stops being live), `FindingsCard` (filters, the table sorted by severity, the finding sheet; it builds the sheet's `review`), `FindingSheet` (the finding with both quotes, Accept and the Reject and Edit dialogs; `DueBadge`), `review.ts` (their state: `useAccept`, `useRejectForm`, `useEditForm`), `ActionPlan` (done toggles), `findings.ts` (order, filters, due dates, edit rules, `useReview`: send, patch the cached finding, refetch; `usePresetFilters`: preset once from `?verdict=`/`?theme=`, then dropped from the URL; `useFindingSheet`: Previous/Next walk a snapshot of the table's order, its own polite region, `useSend({ inside: true })` released on close; `useActionToggles`: optimistic done toggles), `inspections.ts` (the hub and its event, `useInspectionLiveUpdates` (progress patches the cache, a status change refetches, milestones), `useRunInspection` (the post, the Waiting row, refusals and their countdown), refusals, status captions, the running view by state, the checklist). A test file's base name must differ from its neighbours' beyond case and extension (`findings.test.ts` next to `Findings.test.tsx` drops one from the TypeScript program on Windows).
- `settings/`: Settings › Profiles (`/settings/profiles`, `/settings/profiles/:profileId`; `/settings` redirects). `ProfilesScreen` (layout, master and detail below 768px, focus, the polite live region), `ProfileEditor` (permission grid, draft and Save, rename, delete), `UsersCard` (users and the profiles menu), `NameDialog`, `editor.ts` (their hooks: `useProfileEditor`, `useCreateProfile`, `useProfileToggle`, `useNameForm`; `EDITOR_TITLE_ID`), and `profiles.ts` (sorting, grouping, the area read rule).
- `ui/`: shared visual primitives, one file per group, all re-exported by `primitives.ts` (import from there): `buttons.tsx` (`Button`, `secondaryButton` (classes for a link that looks like one), `textAction`, `BackLink` (a detail view's way back to its list), `iconButton` (36px icon-only button classes)), `feedback.tsx` (`Spinner` (its `surface` prop picks a track that shows on card, elevated or mint; `small` is the 12px pill glyph), `Skeleton`, `Notice` (inline notice), `ConnectionNotice` (live updates paused or stopped, with Reconnect), `Message` (`headingId` makes its heading a focus target), `RetryButton`, `ErrorMessage` (load failure with Try again), `DetailUnavailable` (a detail view's not-found or failed card: an h2 by id and an action), `PoliteRegion` (a screen's polite live region)), `badges.tsx` (`StatusPill` (with `IngestionPill` mapped onto it), `Tag`, `TimeBadge`), `progress.tsx` (`ProgressBar`, `Stepper`, `RadialProgress`, `ChecklistRow`), `display.tsx` (`th` (table header cell classes), `rowLink` (a link or button stretched over its `relative` row), `TypeIcon`, `TypeTile`, `IconTile` (the 28px inset tile with a decorative icon), `KpiCard` (inside a `<dl>`), `Disclosure` (a native `<details>`), `Avatar`, `TabStrip`), `citations.tsx` (`CitationChip`, `QuotedPassage` (a stored passage or its quote, highlighted)), `forms.tsx` (`Checkbox`, `ReadOnlyCheckbox`, `TextField`, `TextAreaField`, `SelectField`, `FilterSelect` (compact card-header filter), `DropZone`), `overlays.tsx` (`FormDialog` (`wide` for more than three fields; `ready={false}` holds the submit until something changed), `ConfirmDialog` (a confirmation: `onConfirm` resolves to the refusal to show, or undefined once done; `onClosed`), `dialogPanel` (the dialog surface classes), `uploadDialogPanel`, `Sheet` (named by a `Dialog.Title`, or `aria-labelledby`)), `Logo.tsx` (`Logo`, `LogoMark`), `charts.tsx` (`DonutChart`, `AreaChart`: inline SVG, decorative or a `role="img"` with a summary; the caller gives the text equivalent), `statuses.ts` (`pillVariant`: which pill an ingestion, inspection, verdict or review status shows as), `media.ts` (`useMediaQuery`, the chat breakpoints), `announcer.ts` (`useAnnouncer`: the lines `PoliteRegion` shows, `announce` and `clear`), `dialogs.ts` (`useConfirm`, `ConfirmDialog`'s state; `useFormDialog`, a `FormDialog`'s open-with-reset, submitting, inline error and what was saved, handed to `onSaved` once it has closed), `drop.ts` (`useFileDrop(onFiles, enabled)`, `draggingFiles`) and `focus.ts` (`focusById` (the first of its ids on the page), `useFocusAfterCommit` (for an element the next commit shows), `useShellFocusRequest` (the shell's `focusKey` focuses the page's heading), `useRefocusWhenGone` (a control that held focus went away: its heading takes it), `useFieldErrorFocus` (a field's error, which moves focus to the field)). New primitives go here, never inline in a screen.
- `copy.ts`: every interface string, whole sentences with `{placeholders}` filled by `format()`. Never concatenate sentences. English only until the PT switch. `copy.common` holds the strings several features say (`denied`). Also the `Intl` formatters (`shortDate`, `dateTime`, `calendarDate`, `relativeDays`, `untilReset`, `fileSize`, `languageName`), `daysFromToday` and `localDate`, which reads a date with no time ("2026-11-23") at local midnight, never through `new Date(string)`.
- A component's body is its hooks, then its markup: state and handlers go in named hooks in the feature's `.ts` files (`chat/conversation.ts`, `inspections/review.ts`). A hook more than one feature uses lives in `api/` or `ui/`, never in a feature folder.
- Tests sit next to the code (`*.test.ts(x)`); shared fakes in `src/test/`.

## Boundaries

- The app calls only the core API, on its own origin under `/api` (`API_BASE_URL` in `api/client.ts`), and its SignalR hubs under `/hubs` (`/hubs/documents`, `/hubs/inspections`). The Vite dev server forwards `/api/*` and the `/hubs` WebSockets to the API (`NORMETRY_API_URL`, set by the AppHost; default `http://localhost:5208`), so the API needs no CORS. Never call the AI service: chat goes through the core's `/ai/*` gateway.
- Sign-in: public Keycloak client `normetry-web`, authorization code with PKCE (S256), scopes `openid profile email`. Authority from `VITE_OIDC_AUTHORITY` (set by the AppHost). Only the dev server falls back to `http://localhost:8180/realms/normetry`; a production bundle without it stops at startup with an error naming the variable. The dev server's port is fixed at 5173 because the client accepts only `http://localhost:5173` (`/auth/callback`, `/signed-out`).
- Tokens live in the UserManager's memory only (`InMemoryWebStorage`), never in `localStorage` or `sessionStorage`. Only the PKCE state, which must survive the redirect, goes in `sessionStorage`. A reload goes back through Keycloak, which signs the user straight back in while its session lasts. Refresh uses the refresh token (`automaticSilentRenew`), never an iframe.
- The API client attaches the bearer token to every request. On 401 it refreshes once (shared between concurrent requests) and retries; a second 401, or a failed refresh, starts the session-expired flow (redirect to Keycloak with the current path). A failed background refresh does the same.
- The return path after sign-in must be a same-origin relative path (`safeReturnPath`); anything else becomes `/`.
- Only claim text and citation data from the server reach the screen, and only after `toClaim` checked them (a claim needs a citation; an official link must be http(s)). Refusal, unavailable and quota text comes from `copy.ts`; unknown stream events are ignored.
- `/me`'s `permissions` decide what shows (`can()` in `api/queries.ts`); while `/me` is pending nothing gated shows, and a query is enabled only when its permission is held. Home (`/` redirects to `/overview`) is the first screen the user may open: Overview (`inspections.read` or `documents.read`; without either it redirects to home), then Ask the Regulation (`chat.ask`, `/ask`), then Settings (`profiles.read`); `screenAccess` holds these rules. Choosing an establishment goes to the root of the current section (`/overview`, `/ask`, `/documents`, `/inspections`); Settings stays. A link from another screen asks for the page's heading with `state={arrivalState}`, read with `useArrivalKey()` (Documents, Simulated Inspection). The server still checks every call. Only a 403 from `/me` means "no organization"; a 403 anywhere else is a permission taken away mid-session and refetches `/me` (the query cache's `onError`, `useSend`, the chat).
- The tenant comes from the token on the server. The UI shows the tenant name from `GET /me` and never sends a tenant id. The selected establishment's id is remembered in `localStorage` per tenant and user as a convenience only; the jurisdiction is never stored or sent for use in requests.
- Nothing secret in this folder: everything shipped to the browser is public. `VITE_*` variables end up in the bundle.

## UI rules

- Tokens only (see Stack). One primary button per view. Status colors only for status; none in #53.
- `--text-muted` only on `--bg-sidebar` and `--bg-inset`; `--neutral` never for text (DESIGN.md contrast rule).
- Every interactive element keeps the global mint focus ring (`:focus-visible` in `index.css`); rows and popover items inset it with `focus-visible:-outline-offset-2`.
- Motion through `motion-safe:` utilities only, so `prefers-reduced-motion` turns it off.
- Page titles with React 19's `<title>` element.

## Tooling

From `src/web`:

- `npm ci` · `npm run dev` · `npm run lint` · `npm run format:check` (`npm run format` to fix) · `npm run typecheck` · `npm test` · `npm run build`. CI runs all of them (job `web` in `.github/workflows/ci.yml`).
- The AppHost (`dotnet run --project src/core/Normetry.AppHost` from the repo root) runs `npm install` and then `npm run dev` with `NORMETRY_API_URL` and `VITE_OIDC_AUTHORITY` set; open `http://localhost:5173` and sign in with a demo user from `deploy/keycloak/README.md`.
- Prettier (`printWidth` 100, `endOfLine` auto because of `core.autocrlf`); the repo hook formats edited `.ts`, `.tsx` and `.css` files. ESLint flat config with typescript-eslint (type-checked), react-hooks (including the React Compiler rules) and react-refresh. `eslint-plugin-jsx-a11y` does not support ESLint 10 yet; accessibility is checked by axe in the tests.
- Tests: Vitest in jsdom with Testing Library and user-event. `expectNoAxeViolations()` runs axe-core on the whole document; every screen state gets one. Stub the API with `stubApi()` (a key may name the method: `"DELETE /ai/conversations/c-1"`), stream answers with `sseResponse()`, mock `@microsoft/signalr` with the shared fake hub (`vi.mock("@microsoft/signalr", () => import("../test/signalr"))`; `hubs` and `latestHub()` from `src/test/signalr.ts` let a test play the server's side, as `documents/DocumentsScreen.test.tsx` does), set the window width with `mockViewport()` and sign in with `fakeOidc()` (`src/test/fakes.ts`); no test reaches Keycloak or the API.
- Dependencies are added with a release cooldown: `npm install --before=<two weeks ago> <package>`.
